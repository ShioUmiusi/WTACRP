## 数值自洽（可复算）

1. 885 km/h = 245.833 m/s。按 M 0.73 反推当地声速 336.76 m/s ⇒ ISA 高度 916 m；反过来用同屏 904 米得 a = 336.81 m/s、M = 0.7299，差 0.0001。**885 km/h 是真空速，M 按当地声速算，两个读数同一口径。**
2. 已飞行 18.7 km ÷ 时长 38.3 s = 488.25 m/s = 1758 km/h ≈ M1.45（平均），是当前 M0.73 的两倍 ⇒ 大部分路程在高速段，这一帧已在减速段；与过载 1.2 G、攻角 5.4° 的近弹道姿态一致。
3. 剩余 6.9 km 时 `导引头` 仍是 `惯导` ⇒ 这一帧在中制导段、主动导引头未开。只作游戏侧观测，不用来推断 PL-12 的主动段距离。
4. 歼-16：−95 m/s 与 406 km/h 同时成立 ⇒ 下滑角 atan(342 / 406) = 40.1°。

## 与本项目解析的对应

| HUD 字段 | 能否从 `.wrpl` 得到 | 依据 |
|---|---|---|
| 已飞行 | 能：class 0 位置序列逐点累计 | `web/wrpl-parse.js:3483`（missiles 存 `t/x/y/z`）；播放器已按段画虚线航迹 |
| 时长 | 能：`t` 首末差 | 同上 |
| 平均速度 | 能：已飞行 ÷ 时长 | — |
| 距离 | 不能：WeaponSync 不带目标 uid，没有绑定关系 | `docs/REPLAY-FORMAT.md` §5.4 |
| 过载 / 攻角 / 导引头 | 包里有、现在丢弃：`wsConsumeTail()` 只跳过 `3×u32`、`6×u16`、flags + 8 个 compressed、seeker 计时 | `web/wrpl-parse.js:2093-2108` |

这张图的价值在最后一行：`过载` / `攻角` / `导引头` 既然由回放播放器直接显示，就必然是回放文件里的量；
WeaponSync 尾部那几组被跳过的标量因此有了归口对象，剩下的只是"落在哪个槽"，见
`docs/REPLAY-FORMAT.md` §5.4.1。

同屏的 `已飞行: 18.7 km` / `距离: 6.9 km` / `时长: 38.3 s` 不算这类证据：三项都能由位置序列与时间轴
现算，不需要专门字段。

## 不能证明

- 不构成 PL-12 制导类型的证据。ARH 已由 datamine `cn_pl12.blkx` 的 active radar seeker 确认（`.ref/wrpl-acmi-dev/docs/evidence/missile-guidance.md`）；本图只说明某一帧在惯导段。
- 不构成弹药型号与载机的绑定：屏上没有弹的归属关系。
- 不能与任何本项目产物按 sha 绑定：没有 `.wrpl` 指纹、没有回放时间戳、只有单帧。
- 只证字段**存在**，不证字段的位宽、编码与量纲；1.2 G / 5.4° 是两个样本点，还不足以排除定点缩放以外的解释（例如按 16 位定点 ×0.01 存储）。
- 呼号、队别、`7.4 km` 口径都未标注，不据此改阵营判定。
